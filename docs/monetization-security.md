# 課金・ガチャとセキュリティの方針(蒼星のセイガ)

将来アバター(衣装)や武器のガチャ・課金を入れるための設計メモです。
**いまのゲームは「端末の中のセーブ」と「誰でも書けるスプレッドシート」で動いているため、このままでは課金を安全に扱えません。**
課金を始める前に、下の「必要な土台」を先に作ります。

## 1. いまの作りと弱点

| 部分 | いまの作り | 弱点 |
|---|---|---|
| セーブ | 端末の localStorage | 開発者ツールで所持金・武器を自由に書き換えられる |
| クラウド保存・番付 | Google Apps Script + スプレッドシート | 番付の記録は端末が自己申告(上限チェックのみ) |
| 協力・対戦 | PeerJS(端末どうしの直接通信)、部屋を作った人の端末が審判 | 部屋主の端末を改造すれば勝敗を操作できる |
| 武器錬成(ガチャ) | 端末内で抽選 | 抽選結果を端末で操作できる |

ゲーム内通貨(金)だけで遊ぶ間は「自分のデータを改造しても自分が得するだけ」なので大きな問題ではありません。
**お金が絡んだ瞬間に、改造=不正利用・返金トラブルになります。**

## 2. 今回(v1.6.0)行った対策

- 引き継ぎコードを「ID.合言葉」に変更。合言葉はサーバーにハッシュだけ保存し、読み込み・上書き・番付登録で照合
  (以前は ID を知っていれば誰でも他人のデータを読めて、上書きもできた)
  ※ Apps Script を新しい gas/Code.gs で**再デプロイが必要**
- 番付にありえない記録(撃破数・時間・得点の上限外)を受け付けない
- 協力・対戦: 届いた操作や能力値を型・範囲チェック(改造端末による異常な強さを抑える)、名前の記号を除去
- 部屋番号を 4けた数字 → 6文字英数字(他人の部屋に当てずっぽうで入れないように)。部屋主は参加者を退出させられる
- Content-Security-Policy を設定し、読み込めるスクリプト・通信先を自分のサイトと必要なサービスだけに限定

## 3. 課金を入れるために必要な土台

1. **ログイン付きのサーバー**(おすすめ: Firebase(Authentication + Firestore + Cloud Functions)または Supabase)
   - 所持品・課金通貨・ガチャ結果は**サーバーだけが書き換える**(端末は「引いて」とお願いするだけ)
   - Firestore のセキュリティルールで、本人も所持品を直接書き換えられないようにする
2. **決済**
   - Web(PWA)で売る: Stripe Checkout + Webhook(支払い完了をサーバーが確認してから付与)
   - アプリストアで出す: Google Play / App Store のアプリ内課金(ストア規約で必須)。レシートはサーバーで検証
3. **ガチャ抽選はサーバーで**: 乱数・排出率・天井の回数をサーバーで管理し、履歴を保存
4. **対戦の不正対策**: 本気でランク戦をするなら、部屋主の端末ではなくサーバーで審判する(費用がかかる)。
   それまでは「対戦の結果で課金アイテムが手に入らない」設計にしておく

## 4. 法律・ルールのチェックリスト(日本)

- **確率の表示**: すべての排出物と確率を表示(業界ガイドライン)
- **コンプガチャの禁止**(景品表示法): 「特定の組み合わせを揃えると別の景品」は不可
- **資金決済法**: 有償の課金通貨(石など)を売る場合、未使用残高が基準日に1,000万円を超えると届出・供託が必要。
  有効期限6か月以内なら対象外。最初は「通貨を挟まず直接アイテムを買う」形が簡単
- **特定商取引法の表記**、利用規約、プライバシーポリシー
- **未成年の課金上限**(年齢確認と月額上限)、返金ポリシー
- 素材ライセンスの確認: 課金で売る衣装・武器に、商用・有償配布が許可された素材だけを使う
  (Meshy の無料プランは CC BY 4.0。BOOTH 素材は個別に規約確認が必要)

## 5. 進め方の提案

1. まずゲーム内通貨のみで「アバター(衣装)ガチャ」「武器ガチャ」の中身・見た目を増やす(課金なし)
2. ログインとサーバー保存(Firebase など)へ移行し、ガチャをサーバー抽選にする
3. 規約・表記を整えてから、決済(Stripe または ストア課金)をつなぐ
